# Deploy การคุ้มครองเอกสาร และ retention (นำร่อง)

## ก่อนเปิดรับเอกสารจริง

| ตรวจ | วิธี |
|---|---|
| สำรองฐานและรัน migration | ทำตาม README_PILOT_MHESI.md และซ้อมด้วย `tools/verify_migration_on_dump.py` บนสำเนาก่อน |
| `SECRET_KEY` ยาวอย่างน้อย 32 ตัว | `app.py` ไม่ยอมเริ่มทำงานถ้าค่าไม่ปลอดภัย |
| `SESSION_COOKIE_SECURE=True` | เมื่อให้บริการผ่าน HTTPS |
| `DEMO_MODE=False` | ฐานจริงต้องไม่มีป้าย DEMO และต้องไม่ seed ข้อมูลสาธิต |
| การเข้ารหัสที่พัก | ดูหัวข้อถัดไป แล้วจึงตั้ง `ENCRYPTION_AT_REST_CONFIRMED=True` |
| `SUPPORTED_DISCLOSURE_CLASSES` | ค่าเริ่มต้นคือ `public,internal,restricted` ชั้น `secret` ไม่รองรับในทุกกรณี |
| นโยบายส่งเอกสารให้โมเดล | หน้า "หน่วยงานและสิทธิ์" ของผู้ดูแลระบบ ต้องมีเจ้าของข้อมูลอนุมัติรายการที่เปิดไว้ |

## การเข้ารหัสที่พัก (encryption at rest)

ตัวแอปไม่ได้เข้ารหัสไฟล์หรือฐานข้อมูลเอง จึงต้องพึ่งการเข้ารหัสระดับดิสก์หรือ volume ของเครื่องที่ติดตั้ง

| สภาพแวดล้อม | สถานะ |
|---|---|
| เครื่องพัฒนา (macOS) | รองรับเมื่อเปิด FileVault ไว้ ยังไม่ได้ยืนยันในงานนี้ |
| Docker ตาม `docker-compose.yml` | **ยังไม่ยืนยัน** volume `mysql_data` และ `uploads` ใช้ดิสก์ของ host ต้องเปิด LUKS/dm-crypt หรือดิสก์เข้ารหัสของผู้ให้บริการ cloud ก่อน |
| MySQL | ถ้าต้องการเข้ารหัสระดับตาราง ให้เปิด InnoDB tablespace encryption และ keyring ตามคู่มือ MySQL ยังไม่ได้ตั้งค่าในงานนี้ |
| DEMO (SQLite) | ข้อมูลสมมติเท่านั้น ไม่ต้องเข้ารหัส |

จนกว่าจะยืนยันการเข้ารหัส ให้รอบนำร่องรับเฉพาะเอกสารเผยแพร่หรือเอกสารที่ปกปิดข้อมูลแล้ว
ค่า `document_scope` ของรอบคือ `public_or_redacted` ซึ่งระบบบังคับใช้อยู่แล้ว

## เส้นทางเอกสารและโมเดล

- ทุกไฟล์เก็บข้อมูลแยกกัน 3 อย่าง ได้แก่ ชั้นข้อมูล (`disclosure_class`), ข้อมูลส่วนบุคคล (`personal_data` และ `is_redacted`) และผู้ให้บริการที่จะประมวลผล
  ผู้ให้บริการกำหนดจากระดับ Open/Confidential ของงาน
- `services/model_gate.authorize()` ทำงานก่อนส่งเนื้อหาออกทุกเส้นทาง ได้แก่
  - Domain run (`domain_orchestrator._call_model`)
  - Hybrid KG ใน Domain run (`_run_core_hybrid`)
  - Legacy run และการรันซ้ำ (`app.run_compliance`)
- ไม่มี fallback ระหว่างผู้ให้บริการ ถ้าถูกปฏิเสธ ระบบจะไม่เรียกโมเดลเลย และบันทึก `model_gate_blocked` เฉพาะชื่อไฟล์กับจำนวน ไม่บันทึกเนื้อหา
- ไฟล์จากงานรุ่นก่อนที่ยังไม่มีป้ายกำกับ ระบบอ่านจากระดับเดิมของงาน:
  - Open → เผยแพร่ได้ / ไม่มีข้อมูลส่วนบุคคล
  - Confidential → ไม่เปิดเผย / ยังไม่ทราบ

  กฎเริ่มต้นอนุญาตเฉพาะเส้นทางเดิมของ V14 (Open → Gemini, Confidential → โมเดลภายใน)

## Log ที่บันทึก

ทุกรายการเก็บใน `audit_logs` เป็นรหัสอ้างอิงเท่านั้น ไม่มีเนื้อหาเอกสาร

| เหตุการณ์ | action |
|---|---|
| เปิดไฟล์ต้นฉบับ | `file_open` |
| ดาวน์โหลดรายงาน | `report_download` |
| ส่งออก CSV/JSON/KG/Dashboard/DSV | `domain_report_export`, `round_dashboard_export`, `integration_export` |
| ถูกปฏิเสธสิทธิ์ | `access_denied` |
| บล็อกการส่งให้โมเดล | `model_gate_blocked` |
| ให้หรือถอนสิทธิ์ | `permission_*` |
| วงจรส่งงาน | `workflow_*`, `issue_raise`, `control_judgement` และตาราง `workflow_events` |

## Retention

`python purge_retention.py` แสดงรายงานก่อน เพิ่ม `--apply` เมื่อต้องการลบจริง

| ประเภท | ระยะเวลา (ค่านำร่อง) | การลบ |
|---|---|---|
| การแจ้งเตือนที่อ่านแล้ว | 180 วัน | อัตโนมัติด้วย `--apply` |
| บันทึกการปฏิเสธสิทธิ์ | 2 ปี | อัตโนมัติด้วย `--apply` |
| Audit log อื่น | 5 ปี | อัตโนมัติด้วย `--apply` |
| หลักฐานของรอบที่ปิดแล้ว | 5 ปี | รายงานเท่านั้น เจ้าของข้อมูลต้องอนุมัติการลบ |

ระยะเวลาเหล่านี้เป็นค่าเสนอสำหรับนำร่อง ต้องให้เจ้าของข้อมูลของ สป.อว. ยืนยันก่อนใช้จริง แก้ได้ที่ `services/retention.py`

## ตรวจไฟล์แนบ

`services/file_safety.inspect_pdf` ปฏิเสธไฟล์ในกรณีต่อไปนี้:
- ไม่ใช่ PDF
- มี JavaScript, Launch, EmbeddedFile, RichMedia หรือ XFA
- เข้ารหัสหรือมีรหัสผ่าน
- จำนวนหน้าเกิน `MAX_PDF_PAGES`

ไฟล์เก็บด้วยชื่อสุ่ม ขนาดรวมต่อคำขอไม่เกิน 30 MB
ยังไม่มีการสแกนมัลแวร์ด้วยโปรแกรมภายนอก ถ้าเปิดรับจากภายนอกควรเพิ่ม ClamAV หรือบริการที่หน่วยงานใช้
