# International standards expansion — Ei-GDA V14.3

Research date: 2026-09-23. Scope: the supplied ISO AI standards landscape, including its development box and amendments. Official ISO catalog/product pages take precedence over the image for current status.

## What was added

- 38 new references; 208 new Ei-GDA readiness items.
- Combined international catalog: 54 references (47 published, 7 drafts), 330 items including 122 pre-existing items.
- 7 metadata-only development projects/amendments appear in the Explorer watchlist without scored items.
- All 8 Test Suites retain previous cross-framework mappings and gain the corresponding references from the image.

## Interpretation and provenance

New items are original Ei-GDA readiness questions inferred from the topics explicitly described in official public scope/overview pages. They are not quoted ISO clauses, exhaustive normative checklists, or certification criteria. No clause number is invented. Suggested evidence artifacts are Ei-GDA implementation suggestions, not claimed ISO-mandated forms. Each added item stores its source URL, source topic, and public_scope_derived basis in data/international_standards_v14_3.json; Explorer displays these next to the item.

Pre-existing 122 items retain their identifiers and text for compatibility; this update does not assert that they were independently revalidated against full licensed standards. Full normative clause coverage cannot be established from public summaries. Catalog metadata uses IS, TS and TR to distinguish publication types. TR reports, guidance and terminology are not automatically mandatory certification requirements.

ISO/IEC 42006 concerns AIMS certification bodies; ISO/IEC DIS 42007 concerns conformity-assessment scheme development/operation. Select them only for the relevant organizational role. Draft items are separated under “International Standards — Draft readiness”; unknown publication years remain null. Watchlist projects have no assessment items because substantive public scope was insufficient.

## Apply to an existing installation

From the project directory, with its configured environment:

```bash
.eigda143/bin/python update_international_catalog.py          # read-only preview
.eigda143/bin/python update_international_catalog.py --apply  # additive update
```

The updater backs up affected catalog rows to reports/catalog_before_v14_3_<UTC>.json before the transaction. It adds/updates only the international reference metadata, the new EIGDA-* item identifiers and the eight suite mappings. It does not run seed.py, alter accounts/passwords, delete legacy/custom items, modify assessments/uploads, or change .env. Re-running is idempotent. A database/schema must already exist. A fresh installation still uses the documented migration and seed process; seed_data.py merges this catalog automatically.

## Validation

```bash
.eigda143/bin/python -m unittest discover -s tests -v
```

Tests use an isolated in-memory database and a ThaiD-style session fixture. They check all eight Explorer pages, dashboard draft visibility, graph inclusion, source metadata, unique item codes, repeatable seed merging, additive import, preservation of historical results and existing account credentials. They do not invoke ThaiD or any AI endpoint.
